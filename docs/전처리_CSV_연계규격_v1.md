# 이어:봄 ↔ 별도 전처리 프로그램 CSV 연계규격 v1

상태: Windows 데스크톱 전환을 위한 목표 규격. 현재 `lib/csv.ts`와의 호환을 기준으로 정의한다.

## 공통 약속

- Python 전처리 도구는 기관 원본을 읽어 아래 두 종류의 CSV를 출력한다. 이어:봄 실행 시 Python이나 해당 전처리 도구를 요구하지 않는다.
- 출력 권장 인코딩은 UTF-8 BOM 포함, 구분자는 쉼표, 첫 행은 열 이름이다. 앱은 기존 EUC-KR도 읽는다.
- 셀 안의 쉼표·줄바꿈은 큰따옴표로 감싸고, 큰따옴표 자체는 두 번 쓴다.
- 날짜는 `YYYY-MM-DD`, 시간은 24시간 `HH:mm`이다. 한국 기관 업무 기준 시간대는 Asia/Seoul이다.
- 파일당 1MB 이하. 대기 명단 최대 1,000행, 시간표 최대 500회기. 양쪽 프로그램에서 같은 제한을 검증한다.
- 출력에는 실명·전화·생년월일·주소·진단·상담 내용·원문 메모·가명 대응표를 넣지 않는다.
- 필수 열 누락·중복 열·열 수 불일치·닫히지 않은 따옴표·잘못된 날짜·중복 신청/회기는 파일 전체를 반영하지 않고 행/열 위치를 안내한다.
- 미리보기를 승인한 파일 하나를 전체 성공 또는 전체 취소로 반영한다. 두 파일 사이의 성공/실패는 각각 표시한다.
- v1은 아래 열 이름을 고정한다. 향후 호환되지 않는 변경은 v2로 구분하고 조용히 추측 변환하지 않는다. 파일명은 자유이며 권장 이름은 `participants-v1.csv`, `schedule-v1-YYYY-MM-DD.csv`다.

## 대기 명단

| 열 | 값 |
| --- | --- |
| 가명 ID | `대기자-` 또는 `아동-` + 대문자 영문/숫자 4~32자 |
| 치료 | 작업치료, 물리치료, 언어치료, 감각통합, 상담, 교육, 가족지원 중 하나 이상 |
| 대기 시작일 | 오늘 또는 과거 날짜 |
| 희망 날짜 | 서비스를 희망하는 실제 날짜 |
| 오전 | `09:00` 또는 `09:00–12:00`, 복수 값은 쉼표로 구분 |
| 오후 | `13:00` 또는 `13:00–15:00`, 복수 값은 쉼표로 구분 |
| 상태 | 처리 대기, 처리 완료, 안내 완료, 추가 확인 필요, 신청 취소, 만료 |

`치료` 열은 기존 호환 이름이며 사회사업 서비스도 담는다. 복수 서비스는 CSV 셀을 큰따옴표로 감싼다. 전처리 도구는 동일 서비스 목록의 순서를 항상 같게 출력해 재가져오기 시 같은 신청으로 인식되게 한다.

가명 ID·희망 날짜·정규화된 서비스 목록이 신청 식별 기준이다. 같은 조합의 여러 시간은 한 행에 합친다. ID는 재추출 때 유지하고, 기관 내부 대응표는 별도로 보관한다. 서로 다른 기관의 같은 문자열 ID가 같은 사람이라는 의미는 없다. v1 설치본은 한 기관의 업무 DB를 기준으로 한다.

시간 값 하나는 그 시간부터 30분을 뜻한다. 범위는 30분 전체 회기를 포함해야 후보가 된다. 오전/오후 중 적어도 하나에 값이 필요하다. 상태 열이 빈 경우 현재 호환 동작은 `처리 대기`이므로 전처리 도구는 상태를 명시적으로 출력하는 것을 원칙으로 한다.

```csv
가명 ID,치료,대기 시작일,희망 날짜,오전,오후,상태
대기자-SAMPLE01,작업치료,2026-01-01,2030-01-07,"09:00,10:00",,처리 대기
대기자-SAMPLE02,상담,2026-01-01,2030-01-07,,13:00–15:00,처리 대기
```

예시는 가상 자료이며 운영 날짜를 뜻하지 않는다. 체험용 자료는 앱이 유효한 미래 업무일로 생성한다.

같은 신청은 갱신하고 CSV에 없는 기존 신청은 보존한다. 신청을 없애려면 `신청 취소` 또는 `만료` 상태로 같은 신청을 재반영한다. 여러 희망 날짜는 한 파일에 포함할 수 있으나 날짜별 건수와 지난 날짜를 미리보기에 표시한다. 현재 방식은 같은 가명 ID의 대기자를 활성 상태로 갱신하므로, 가져오기 시 중지된 대상자의 재활성화 건수를 명시하고 사용자 확인을 받도록 데스크톱 화면을 보완한다.

## 서비스 시간표

| 열 | 값 |
| --- | --- |
| 일자 | 해당 회기의 실제 날짜 |
| 부서 | 위 서비스 목록의 값 하나 |
| 담당자 코드 | 대문자 영문 2~12자 + `-` + 대문자 영문/숫자 1~16자, 예: `OT-01` |
| 시작 | 회기 시작 시간 |
| 종료 | 회기 종료 시간 |
| 예약 코드 | 가명 예약 코드, 대문자 영문·숫자·`_`·`-` 1~24자 |

예약 코드는 형식이 맞더라도 전화번호·생년월일·실명을 넣지 않는다. 담당자 실명 대신 일관된 내부 코드를 사용한다.

파일 하나에는 날짜 하나만 포함한다. 같은 날짜·담당자·시작 시간은 한 번만 등장한다. 요일은 앱이 날짜에서 계산한다. 08:30–12:00 / 13:00–18:00 중 정각 또는 30분 시작의 30분 회기만 지원한다. 전처리 도구는 10분 칸 원본의 표기 방식을 그대로 내보내지 말고 실제 회기 단위로 변환한다. 자동으로 판단할 수 없는 예약은 전처리 단계에서 검수 대상으로 표시한다.

```csv
일자,부서,담당자 코드,시작,종료,예약 코드
2030-01-07,작업치료,OT-01,09:00,09:30,SAMPLE01
2030-01-07,상담,SW-01,13:00,13:30,SAMPLE02
```

반영은 해당 날짜 시간표의 전체 교체다. 이미 등록된 결석·연결 회기를 없애거나 담당자·서비스·시간을 바꾸는 교체는 거부한다. 빈 셀을 자동 결석 회기로 만들지 않으며, 최종 결석 등록은 앱에서 담당자가 확인한다.

## 호환성 검수 자료

전처리 도구와 이어:봄 양쪽에서 같은 가상 파일을 사용해 아래를 확인한다.

1. 100명·복수 날짜·복수 서비스·복수 가능 시간의 왕복 변환.
2. 재추출·재가져오기에도 동일 ID와 신청이 중복 생성되지 않음.
3. UTF-8 BOM 및 EUC-KR, 한글·공백 파일 경로 정상 처리.
4. 날짜 오류·중복 행·시간표 복수 날짜·행 수 초과가 전체 거부됨.
5. 실패 후 기존 DB·감사 기록이 부분 변경되지 않음.
6. 데이터 안의 식별정보와 원문 메모가 출력 파일 및 앱 로그에 남지 않음.

전처리 프로그램 소스와 실제 출력 파일은 아직 이 설계에서 검증하지 않았다. 구현 시 가상 출력 샘플로 위 계약을 확인한다.
