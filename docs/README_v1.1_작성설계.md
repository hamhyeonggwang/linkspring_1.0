# README v1.1 제출 문서 작성 설계

## 1. 목적과 기준

최종 `README.md`는 공모전에서 제공한 `readme_v1.1.md`의 기본 양식을 제출 문서의 최상위 구조로 사용한다. 원본 양식의 번호, 제목, 필수 표, 체크리스트와 개인정보·AI 윤리 5개 문항은 삭제하거나 이름을 바꾸지 않는다.

현재 저장소의 `readme_submission_v1.1.md`를 내용 초안으로 사용하되, 최종 문서는 Windows 로컬 데스크톱 앱 1.1.0의 실제 동작과 검증 결과를 기준으로 다시 작성한다. 웹 개발 버전, Cloudflare D1, Sites 로그인에 관한 내용은 현재 제출 프로그램의 설치·실행 방법으로 설명하지 않는다.

문서가 길어질 경우에도 필수 양식 안에는 심사에 필요한 핵심만 두고, CSV 상세 규격·빌드 방법·검증 로그는 별도 문서 링크 또는 4.5 이후의 부록으로 제공한다.

2. `## 1. 팀 기본 정보`

   - `### 3.2 시행착오와 개선`
   - `### 3.3 향후 계획 및 임팩트 확산`

   - `### 4.1 외부 지원 범위`

원본의 안내 문장은 최종 제출본에서 실제 답변으로 교체한다. 원본 표는 열 구조를 유지한다. 해당자가 없는 표 행도 삭제하지 않고 `없음`과 그 근거를 적는다.

## 4. 양식에 내용을 추가하는 규칙

필수 구조를 유지하면서 설명이 더 필요한 경우 다음 두 방법만 사용한다.

### 4.1 필수 항목 내부의 보조 제목

원본이 이미 요구하는 `솔루션 개요`, `솔루션 사용 링크`, `설치 및 실행 방법`, `주요 기능`, `AI 활용 내용`, `AI 성능 개선 시도`는 그대로 사용한다. 이용자용·관리자용 가이드 안에는 `준비 사항`, `사용 순서`, `데이터와 백업`, `운영상 주의사항` 같은 4단계 제목을 추가할 수 있다.

### 4.2 4.5 이후의 부록

심사자가 재현하거나 검증하는 데 필요한 상세 자료는 다음 부록으로 추가한다.

- `부록 A. 지원 CSV 형식`: 기관 대기명단과 치료사 시간표의 열 이름, 인코딩, 행 제한, 익명 표시 조건
- `부록 B. 기술 검증 결과`: 자동 테스트 31개, Electron UI 업무 흐름, 설치파일 검증, Windows 실기기 미검증 사실
- `부록 C. 상세 문서`: Windows 사용 안내, CSV 연계 규격, 구현 검증 기록 링크

부록은 본문의 답변을 대신하지 않는다. 예를 들어 2.3에는 반드시 짧은 사용 순서가 있어야 하며, 상세 절차만 부록으로 연결한다.

## 5. 표현과 증거 원칙

- `현장 적용`, `실사용 완료`, `업무 시간 단축`은 실제 기관에서 측정하거나 확인한 증거가 있을 때만 사용한다.
- macOS에서 생성한 Windows 설치파일은 `Windows용 설치파일 생성 및 패키지 검사 완료`로 표현한다. Windows PC에서 설치·실행하지 않았다면 `Windows 실제 설치 검증 완료`라고 쓰지 않는다.
- 합성 데이터의 자동 테스트와 Electron UI 검증은 기술 검증이며, 현장 적용 결과와 구분한다.
- Claude는 선택 기능으로 설명한다. 앱의 핵심 후보 계산은 규칙 기반이며 Claude가 자동 배정한다고 표현하지 않는다.
- CSV의 `아동이름`은 기관이 만든 고유한 익명 표시라는 전제임을 밝힌다. 생년월일은 내부 ID 생성이나 저장에 사용하지 않는다.
- 로컬 앱에서는 원본 CSV를 외부 서버로 전송하지 않는다. Claude 사용을 켜고 담당자가 분석을 실행한 경우에도 허용된 일정 토큰만 전송한다고 설명한다.
- 확정 연결 취소, 여러 PC 동기화, EMR·문자 자동 발송처럼 구현하지 않은 기능은 향후 계획 또는 한계에 둔다.
- `[확인 필요]`, 로컬 절대 경로, 예시 URL, 실제 API 키나 계정정보는 최종 제출 전에 모두 제거한다.

설치파일은 일반 Git 커밋에 포함하지 않고 GitHub Release 자산으로 게시한다. 저장소의 Source code ZIP을 실행파일로 안내하지 않는다. SHA-256 체크섬도 같은 Release에 첨부한다.

## 8. 완료 조건

최종 `README.md`는 다음 조건을 모두 만족해야 한다.

- 원본 `readme_v1.1.md`의 모든 필수 제목·표·체크리스트·윤리 문항이 존재한다.
- 현재 Windows 로컬 앱 1.1.0 기준으로 설치와 운영 방법이 일관된다.
- 모든 링크가 저장소 밖에서도 열리며 로컬 절대 경로가 없다.
- 확인되지 않은 주장과 예시 값이 실제 결과처럼 적혀 있지 않다.
- 제출자가 제공한 팀·지원·현장 결과 정보가 반영된다.
- 체크리스트의 `[X]`마다 본문 또는 연결 문서에서 확인할 수 있는 근거가 있다.
- 개인정보, 실제 CSV, API 키, 비밀번호, 인증 토큰이 포함되지 않는다.
- Markdown 표와 링크가 GitHub에서 정상적으로 렌더링된다.

최종화 순서는 `readme_submission_v1.1.md` 갱신 → 미확정 항목 확인 → `README.md`로 반영 → 링크·체크리스트 검수 → 커밋 순으로 진행한다.
