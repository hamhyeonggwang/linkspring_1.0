# Windows 설치형 빌드 검증

작성일: 2026-09-17

## 산출물

- `release/LinkSpring-Setup-1.0.0-x64.exe`: Windows x64용 전체 NSIS 설치파일. 실행 환경 포함.
- `release/SHA256SUMS.txt`: 최종 설치파일 SHA-256.
- `release/verification.json`: 패키지 검사 결과.
- 설치/업무 안내: `docs/Windows_사용안내.md`.

## 구현

기존 React 화면과 검증된 업무 규칙을 재사용하며, Electron 주 프로세스에서 SQLite를 사용한다. 화면은 격리된 preload API로만 저장소에 접근한다. 개발 서버나 외부 웹 호스팅을 실행하지 않는다. 기존 계획의 better-sqlite3 대신 Electron 44.4.1에 내장된 Node 24.21.0의 `node:sqlite`를 사용해 별도 네이티브 모듈 배포를 제거했다. [Node SQLite 공식 문서](https://nodejs.org/api/sqlite.html)

업무/체험 저장소 분리, 다음 평일 기준 예시 생성, 직접 일정 등록, 로컬 백업/복원, 마이그레이션 전 자동 백업, 선택적 Claude 키 암호화 저장을 구현했다. `contextIsolation`, sandbox, Node 통합 차단, CSP, IPC 호출자 검사, 작업 허용 목록과 외부 탐색 차단을 적용했다. [Electron 보안 권고](https://www.electronjs.org/docs/latest/tutorial/security)

## 확인한 사항

- TypeScript 타입 검사 및 ESLint 통과.
- 기존 업무 규칙·Cloudflare D1 회귀 테스트 20개 통과.
- 데스크톱 SQLite 테스트 5개 통과: 재시작 유지, 중복 확정 거부, WAL 포함 백업/복원 및 복원 전 자동 백업, 변조 스키마 복원 거부, 트랜잭션 롤백, 업데이트 전 자동 백업.
- macOS에서 같은 Electron 앱을 격리된 테스트 프로필로 실행해 렌더링 및 IPC 동작 확인.
- 실제 Electron 화면에서 체험 생성 → 연결 확정 → 안내 완료 기록 → 업무 저장소 복귀 확인.
- API 키 없는 규칙 분석 및 허용되지 않은 IPC 요청 거부 확인.
- 패키지 허용 목록 검사로 환경 파일·업무 DB·키 설정 파일·node_modules·소스맵 제외 확인.
- Windows 실행 파일의 PE x64 형식 및 전체 설치파일 생성 확인.
- 최종 NSIS 설치파일 7-Zip 무결성 검사 통과. 설치파일에서 추출한 `app.asar`와 검사한 배포 패키지의 SHA-256 일치 확인.
- 설치파일에 들어간 `app.asar`를 macOS Electron에서 직접 실행해 위 핵심 업무 검증을 재통과. Windows 네이티브 실행 검증과는 구분한다.

최종 설치파일 크기: 111,478,855바이트(약 106.3MiB).

SHA-256: `a03454da8093cb05d527c35590d291e50aafd7e27581085cd7f1f7cc68751b32`

## 아직 확인하지 않은 사항과 범위

- 이 작업 환경은 macOS다. Windows 10/11의 새 PC에서 설치·첫 실행·재부팅·업데이트·제거를 실제 수행한 결과는 아니다.
- Windows DPAPI 저장/복호화와 한글 사용자 경로, 기관 보안 프로그램의 허용 여부는 Windows 현장에서 확인해야 한다.
- 코드 서명 인증서가 없어 서명하지 않았다. 게시자 경고가 표시될 수 있다.
- GitHub Releases 업로드는 수행하지 않았다. 설치파일은 로컬 `release/`에 생성했다.
- 확정 취소 UI, 여러 PC 동시 사용, 자동 업데이트, 임의 회기 길이는 이번 설치형 버전 범위에 포함하지 않았다.
- 사용자 앱 코드의 공개 라이선스는 별도 확정 대상이다. 타사 라이브러리 고지는 패키지에 포함했다. 저장소 공개만으로 코드의 재배포 권한을 임의 부여하지 않았다.

## Windows 인수 확인 순서

1. 개발 도구와 네트워크가 없는 Windows 10/11 x64 PC에서 설치파일 실행.
2. 시작 메뉴·바탕화면 실행 후 예시 체험의 연결·안내 완료 확인.
3. 실제 업무 저장소에 가상 대기자 및 직접 일정을 등록하고 앱 종료/재실행 후 유지 확인.
4. 백업, 데이터 변경, 복원 후 원래 데이터와 이전 상태 자동 백업 확인.
5. 한글 계정명·공백 포함 경로에서 같은 절차 확인.
6. 동일/후속 버전 재설치 및 제거 후 데이터 보존 확인.
7. 기관의 실행 정책과 공개 라이선스 확정 후 GitHub Releases에 설치파일·사용 안내·체크섬 배포.
