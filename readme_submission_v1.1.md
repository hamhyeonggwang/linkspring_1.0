## 2. AI 솔루션

### 2.1 문제 정의

치료뿐 아니라 상담, 교육, 가족지원 등 다양한 사회사업에는 대기 명단이 존재합니다. 현재 서비스를 이용하는 대상자가 당일 결석 의사를 기관에 전달하면, 담당자는 이후 대기자의 가능 시간과 기관 내 가용 일정을 각각 확인하기 위해 100여 명의 스케줄을 수동으로 살펴보고 아이의 치료 기회를 연결해야 합니다. 가용 시간표와 대기 명단을 대조하는 과정이 반복되며, 기다리고 있는 대기자에게 기회가 이어지기 전에 시간이 소진되거나 처리 기준과 이력이 사람마다 달라질 수 있습니다.

주 이용자는 빈 회기와 사회사업 일정을 관리하는 기관 코디네이터입니다. 현재 방식은 전화, 사내 메신저 또는 별도 명단을 오가며 대기자와 가용 일정을 확인해야 하므로, 식별정보 노출 위험, 누락, 후보 비교의 일관성 저하, 안내 완료 여부 추적의 어려움이 있습니다. 대기 중인 아동·보호자에게도 결석으로 생긴 기회가 언제 누구에게 연결되었는지 알기 어렵습니다. 이어:봄은 문제를 ‘빈 스케줄을 채워 수익을 만드는 일’이 아니라 ‘기다리고 있는 대기자에게 이미 생긴 서비스 기회를 이어주는 일’로 다시 정의합니다.

### 2.2 AI 솔루션 소개

#### 솔루션 개요

이어:봄은 현재 치료 스케줄을 이어주는 기능에서 출발해, 비영리 기관이 제공하는 다양한 서비스의 대상자와 사용 가능한 일정을 연결하는 시스템으로 확장될 수 있도록 설계되어있습니다.

1. 결석 문자 원문에서 일정 토큰만 브라우저에서 추린 뒤 담당자가 전송 내용을 확인하고 날짜·시간·서비스·담당자 코드를 구조화합니다.
2. 익명 시간표 CSV와 대기 아동 CSV를 화면에서 검증하고, 원본 개인정보 대신 가명 ID·치료 유형·가능 시간·대기 시작일만 저장합니다.
3. 가능한 시간과 치료 유형이 맞는 후보를 대기 경과일이 긴 순서로 제시합니다.
4. 코디네이터가 최종 후보를 확인·확정하고, 개인정보가 없는 보호자 안내문을 생성합니다.
5. 연결 완료와 보호자 안내 완료를 별도 상태와 감사 로그로 기록합니다.

핵심 관점은 스케줄의 연결을 대기자의 기회 회복으로 보는 것입니다. 비영리 기관의 치료·교육·상담·재활 프로그램에도 같은 구조를 적용해, 취소나 공백으로 생긴 자원을 기다리던 사람에게 신속하고 공정하게 이어주는 것을 목표로 합니다.

결석 문자 구조화는 서버의 Anthropic Claude Messages API를 선택적으로 사용하며, API 키가 없거나 호출에 실패하면 서버 규칙 분석으로 보완하고 누락된 항목은 직접 입력합니다. API 키는 서버 환경변수로만 관리하고 브라우저에 노출하지 않습니다. 후보 정렬도 명시적 규칙으로 동작하며 자동 확정하지 않습니다.

#### 설치 및 실행 방법

필요 환경은 Node.js `22.13.0 이상`과 npm입니다.

```bash
cd /Users/ham1234/Documents/OTwiki/project/linkspring-main
npm ci
npm run db:local
LOCAL_DEV_AUTH=1 npm run dev
```

브라우저에서 개발 서버 주소를 열어 확인합니다. 배포 시 `.openai/hosting.json`의 D1 바인딩 이름 `DB`가 연결되어야 하며, 데이터베이스 마이그레이션 SQL은 `drizzle/` 폴더에 있습니다. 비밀키·비밀번호·인증 토큰은 저장소에 추가하지 않습니다.

AI 구조화를 사용하려면 배포 환경의 서버 비밀값에 `CLAUDE_API_KEY`를 설정하고, `CLAUDE_MODEL`을 지정합니다. 실제 키는 서버 비밀값으로 설정합니다. 기존 로컬 `.env.local`은 유지하며 소스·제출 파일에 포함하지 않습니다. 키나 모델이 없으면 규칙 분석으로 전환합니다. 로컬 인증 우회는 가상 데이터 확인용이며 운영에서는 끕니다.

#### 주요 기능

- 결석 문자 입력 및 안전한 정보 추출: 원문을 저장하지 않고 허용된 일정 토큰만 추출해 구조화합니다. 지난 날짜 및 월일만 있는 날짜는 제외하므로 직접 확인합니다.
- 처리 대기 큐: 빈 회기 상태를 `처리 대기`, `추가 확인 필요`, `연결 완료`로 관리합니다.
- 후보 비교: 치료 유형, 가능 시간, 활성 상태를 기준으로 후보를 좁히고 대기 경과일 순으로 표시합니다.
- 사람의 최종 확정: 자동 배정 없이 코디네이터가 후보를 선택하거나 보류합니다.
- 당일 익명 시간표 CSV: 예약 코드만 저장하고 빈 셀은 자동 빈 회기로 만들지 않습니다.
- 대기 아동 CSV: 기관이 사전에 발급한 가명 ID가 있는 CSV만 반영합니다. 이름·생년월일에서 해시를 만들지 않습니다. 희망 날짜·서비스·가능 시간·상태를 검증합니다.
- 안내문 생성·복사·완료 기록: 사전 정의된 문구에 날짜·시간·서비스만 넣고 실제 안내 여부를 별도로 기록합니다.
- 운영 원칙 및 이력: 감사 로그와 추가 확인 목록으로 사람이 검수한 결정을 남깁니다.

#### (선택) AI 성능 개선 시도

일정 토큰만 Claude Messages API로 보내며 단일 도구 입력 JSON을 스키마로 검증합니다. 누락·형식 오류·호출 실패 시 규칙 분석으로 전환하고, 15초 시간 제한을 둡니다. 원문·API 오류 본문은 로그로 남기지 않습니다. 가상 일정으로 실제 Claude 연동 응답을 확인했으며 현장 추출 정확도는 아직 측정하지 않았습니다.

### 2.3 이용자용 가이드

1. `서비스 일정`에서 당일 개인정보가 제거된 시간표 CSV를 불러옵니다.
2. `대기자 관리`에서 대기 아동 CSV를 불러오거나 가명 ID로 직접 등록합니다. 원본 이름·생년월일은 저장하지 않습니다.
3. 결석 문자를 `결석·빈 회기 등록`에 붙여넣고 `일정 정보만 추출`을 누릅니다. 전송 내용을 확인해 Claude로 분석한 뒤, 추출 결과를 수정·확인하고 등록합니다.
4. `처리 대기`에서 회기를 열고 후보의 가능 시간, 치료 유형, 대기 경과일과 최근 연결 이력을 확인합니다.
5. 적절한 후보를 선택해 연결을 확정합니다. 판단이 어려우면 `추가 확인 필요`로 보류합니다.
6. 생성된 안내문을 확인해 복사하고 실제 기관 연락 채널에서 전달한 뒤 `실제 안내 완료로 기록`을 누릅니다.

주의: 화면에 표시되는 후보는 추천 목록이며 자동 확정이 아닙니다. 시간표 또는 대기 명단을 반영하기 전에 날짜·열 구조·가명 처리 결과를 확인하고, 실제 개인정보가 들어간 원본 파일은 업로드하지 않습니다.

### 2.4 관리자용 가이드

#### 구조

- `app/page.tsx`: 화면·미리보기·수정·최종 확인 흐름
- `lib/domain.ts`, `lib/csv.ts`: 후보 규칙·시간 검증·CSV 검증
- `lib/state-actions.ts`, `lib/state-store.ts`: 서버 검증·버전 충돌 차단·원자적 저장
- `lib/absence.ts`, `lib/access.ts`: Claude 응답 검증·보완 처리·권한 정책
- `app/api/state/route.ts`: 슬롯·대기 아동·희망 일정·설정·시간표·감사 로그의 조회 및 저장 API
- `db/schema.ts`: Cloudflare D1용 Drizzle 스키마
- `drizzle/`: 데이터베이스 마이그레이션 SQL
- `worker/index.ts`, `vite.config.ts`: Vinext/Vite와 Cloudflare Worker 실행 구성
- `.openai/hosting.json`: Sites 프로젝트 및 D1 바인딩 설정

#### 운영 준비 및 방법

Node.js 22.13.0 이상에서 의존성을 설치하고 `npm run dev`로 로컬 점검합니다. 배포 환경에는 D1 바인딩 `DB`를 연결하고 `drizzle/` 마이그레이션을 적용합니다. 운영자는 매일 익명 시간표와 대기 아동 명단을 먼저 반영하고, 처리 대기·추가 확인·연결·안내 완료 상태와 감사 로그를 확인합니다.

#### 운영상 유의점

- 원본 CSV와 결석 문자 원문은 저장·공유하지 않습니다.
- 가명 ID만 사용하고 이름·연락처·생년월일을 안내문이나 로그에 넣지 않습니다.
- 규칙이 추출한 회기 정보와 후보 순서는 사람이 확인합니다.
- 기관 메시지 API는 현재 연결 예정 상태이므로 안내문 복사 후 기관 채널에서 직접 전송합니다.
- D1 연결이 없으면 `/api/state` 저장이 실패할 수 있으므로 배포 전 바인딩과 마이그레이션을 확인합니다.

## 3. 임팩트 계획서

### 3.1 현장 적용 결과

제출 시 다음 근거를 비식별 형태로 보완합니다.

- 적용 기관·기간·처리한 결석/빈 회기 건수

- 후보 확인 누락 또는 안내 미완료 건수 변화
- 코디네이터와 치료사의 익명 후기
- 팀의 AI 활용 방식 변화와 추가 도입 의향

### 3.2 시행착오와 개선

초기 설계에서 자동으로 빈 회기를 만들거나 자동 배정하면 잘못된 연결의 책임이 불명확해질 수 있었습니다. 이를 개선해 시간표의 빈 셀을 기회로 자동 생성하지 않고, 결석 등록으로 확인된 경우에만 빈 회기를 생성하도록 했습니다. 후보도 자동 확정하지 않고 가능 시간·치료 유형·대기 경과일을 함께 보여주며 코디네이터가 확정하게 했습니다.

또한 CSV의 인코딩과 열 누락을 고려해 UTF-8/EUC-KR 읽기, 필수값 검증, 여러 날짜 경고, 치료사 수 경고를 넣었습니다. 결석 문자 원문은 서버에 보내기 전에 연락처와 이름 패턴을 가리고, 안내문은 개인정보를 포함하지 않도록 했습니다.

남은 한계는 외부 LLM 기반의 다양한 문장 표현 처리, 기관 메시지 API 연동, 실제 현장 데이터에 대한 정량 검증이 아직 없다는 점입니다.

### 3.3 향후 계획 및 임팩트 확산

1. 실제 익명화된 문장 샘플로 추출 정확도와 예외 유형을 측정합니다.
2. 필요할 때만 보안 검토를 거친 모델을 연결하되, 모델 결과는 구조화 보조로 제한하고 사람의 최종 승인을 유지합니다.
3. 기관별 치료 시간표 열 구조를 설정으로 관리하고, 메시지 API는 발송 전 미리보기·재확인·실패 재처리를 포함해 연동합니다.
4. 처리 시간, 연결률, 안내 완료율, 보류 사유를 익명 통계로 모아 여러 치료실의 운영 개선에 활용합니다.
5. 치료 외에도 상담, 교육, 가족지원, 지역사회 프로그램 등 비영리 기관의 서비스 슬롯과 대기자를 연결하는 공통 데이터 구조로 확장합니다. 기관의 수익보다 대상자의 대기 기간 단축과 기회 접근성 개선을 핵심 성과로 측정합니다.

### 4.5 개인정보·AI 윤리

1. **수집·이용·전송:** 운영에 필요한 가명 ID, 치료 유형, 가능 시간, 대기 시작일, 최근 연결 이력, 회기·치료사 정보를 사용합니다. 결석 문자 원문은 브라우저에서 일정 토큰만 추립니다. 담당자가 전송 내용을 확인하고 AI 분석을 선택한 경우에만 일정 토큰이 서버를 거쳐 Claude API로 전송됩니다. 원본 시간표·대기 아동 CSV는 브라우저에서 해석하고, 저장 시 익명·가명 데이터만 D1에 기록합니다.
2. **동의와 근거:** 실제 기관에서 사용할 때는 기관의 개인정보 처리 근거와 보호자 안내·동의 절차를 확인해 적용해야 합니다. 현재 저장소에는 실제 이용자 동의 기록이 포함되어 있지 않으므로 제출 기관의 절차를 `[확인 필요]`로 보완합니다.
3. **처리 방식과 AI 고지:** 원문을 영구 저장하지 않고 화면 메모리에서 처리하며, 허용된 일정 토큰만 Anthropic Claude Messages API로 보내 구조화합니다. 서비스 화면과 이용자 가이드에 AI 보조 처리 사실, 전송 항목, 서버 키 관리 방식을 고지합니다. API를 사용할 수 없을 때는 규칙 기반 처리로 전환합니다.
4. **오류 수정 절차:** 추출 결과를 등록 전에 사람이 확인하고, 후보는 자동 확정하지 않습니다. 후보가 없거나 판단이 어려우면 `추가 확인 필요`로 보류하고, 연결·안내 완료·보류는 감사 로그로 남겨 관리자 화면에서 확인합니다. 확정 취소·완료 기록 수정 화면은 아직 제공하지 않습니다.
5. **피해 방지:** 치료 연결은 의료적 판단이나 진단을 자동화하지 않으며, 시간·치료 유형 기반 후보 제시에 한정합니다. 안내문은 개인정보를 포함하지 않고, 실제 발송은 기관 채널에서 사람이 확인합니다. API에는 확인된 일정 토큰만 보내고 모델 응답을 자동 배정에 사용하지 않으며, 최종 연결은 코디네이터가 검수합니다.
