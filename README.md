# 이어:봄(LinkSpring)

비영리 기관의 빈 서비스 일정과 대기자를 연결하는 코디네이터 업무 프로그램입니다. 치료에서 출발해 상담·교육·가족지원으로 확장하며, 수익보다 기다리는 사람의 기회를 우선합니다. 제출용 배포 형태는 **Windows 로컬 데스크톱 앱**입니다. 기존 웹 개발 코드는 유지합니다.

## Windows 설치형 사용

`release/LinkSpring-Setup-1.0.0-x64.exe`를 Windows 10/11 64비트 PC에서 실행해 설치합니다. GitHub 배포 시 이 파일을 Releases에 첨부해야 하며, Source code ZIP은 설치파일이 아닙니다. 기본 업무에는 인터넷·Node.js·Python·API 키가 필요하지 않습니다. 첫 실행의 **예시로 체험**에서 가상 데이터로 업무 흐름을 확인할 수 있습니다.

Electron과 내장 `node:sqlite`를 사용하며, 실제 업무와 체험 데이터는 별도 파일에 저장합니다. 앱 상단에서 일정 직접 등록·백업·복원·선택적 Claude 설정을 제공합니다. [Windows 사용 안내](docs/Windows_사용안내.md)를 참조하세요. 이 빌드는 코드 서명되지 않았으며, Windows에서의 실제 설치·제거 검증은 별도로 필요합니다.

### 개발자 빌드

```bash
npm ci
node node_modules/electron/install.js
npm run desktop:test
npm run desktop:dist
npm run desktop:verify
```

설치파일과 SHA-256 검증 파일은 `release/`에 생성됩니다. 개발용 실행은 `npm run desktop:build` 후 `npm run desktop:start`입니다. 빌드는 `.env.local`을 읽지 않으며 설치파일에 API 키·업무 DB·개발 서버를 포함하지 않습니다. 배포 후 데이터는 `%LOCALAPPDATA%\LinkSpring\data`에 유지됩니다. Python 전처리 프로그램은 별도 배포 대상입니다.

아래 내용은 기존 웹 개발 버전의 실행 및 운영 설정입니다.

## 로컬 실행

Node.js 22.13 이상이 필요합니다. 기존 `.env.local`의 비밀값은 유지하세요.

```bash
cd /Users/ham1234/Documents/OTwiki/project/linkspring-main
npm ci
npm run db:local
LOCAL_DEV_AUTH=1 npm run dev
```

터미널에 표시되는 주소(기본 `http://127.0.0.1:5173/`)로 접속합니다. `LOCAL_DEV_AUTH=1`은 로컬 가상 데이터 점검용이며, 서버는 루프백 주소에서만 수신합니다. 실제 기관 데이터는 이 모드에 넣지 마세요. 기본 실행은 인증이 필요하고, 허용된 계정이 없으면 접근을 거부합니다.

로컬 D1은 `.wrangler/state/v3/d1`에 보관됩니다. 다시 실행해도 유지되며 `npm run db:local`은 아직 적용되지 않은 마이그레이션만 적용합니다. 이 명령은 운영 DB에 접속하지 않습니다. 손상됐던 기존 lockfile은 무시 파일 `package-lock.corrupt.backup.txt`에 보존했고 현재 `package-lock.json`은 정상 재생성했습니다.

## 운영 환경 설정

| 설정 | 용도 |
| --- | --- |
| D1 바인딩 `DB` | 명단·희망 일정·시간표·연결·감사 로그 저장 |
| `COORDINATOR_EMAILS` | 접근을 허용할 ChatGPT 로그인 이메일 목록, 쉼표 구분. 빈 값은 전원 거부 |
| `CLAUDE_API_KEY` | 서버 비밀값. 화면·소스·제출 문서에 넣지 않음 |
| `CLAUDE_MODEL` | 기관이 사용할 Claude 모델 ID. `.env.example`은 기존 선택값 예시 |
| `LOCAL_DEV_AUTH` | 운영에서는 반드시 `0` |

Claude 키 또는 모델이 없거나 응답이 실패하면 규칙 분석으로 전환합니다. 누락 항목은 빈칸으로 남아 직접 입력해야 합니다. 실제 키 파일은 새로 생성하지 않았습니다. 로컬 개발은 기존 `.env.local`을 읽으며, `.dev.vars`가 있으면 Wrangler의 파일 우선순위를 확인하세요. [Cloudflare 환경변수 안내](https://developers.cloudflare.com/changelog/post/2025-08-08-dot-env-in-local-dev/)

운영 인증은 Sites의 ChatGPT 로그인 게이트웨이가 검증해 주입하는 사용자 헤더를 신뢰합니다. 해당 헤더를 외부에서 위조할 수 없도록 보장하는 Sites 환경에서 배포해야 합니다. 일반 공개 Worker에 그대로 노출해서는 안 됩니다. 운영 D1 바인딩·모든 마이그레이션·허용 계정 설정과 인증 게이트웨이를 확인한 뒤 배포합니다. 이번 작업에서는 운영 배포 및 실제 기관 데이터 반영을 하지 않았습니다.

## 업무 순서

1. **서비스 일정**에서 가명 담당자 코드로 된 시간표 CSV를 읽고 미리보기를 확인해 반영합니다.
2. **대기자 관리**에서 기관이 발급한 가명 ID로 등록하거나 날짜별 희망 일정 CSV를 반영합니다. 실명·생년월일에서 해시 ID를 만들지 않습니다.
3. 시간표에서 실제 결석을 확인한 회기를 선택하거나 **결석·빈 회기 등록**을 엽니다. 문자 분석은 선택 사항입니다. 일정 정보 추출 → 전송 내용 확인 → Claude 분석 → 날짜·시간·서비스·코드 수정 → 등록 순서입니다.
4. **처리 대기**에서 후보의 가능 시간·서비스·대기 기간·최근 연결을 비교합니다. 대기 기간이 긴 순, 동률이면 최근 연결이 오래된 순(없음 우선), 이후 가명 ID 순입니다.
5. 코디네이터가 최종 확정합니다. 같은 시간의 중복 배정, 이미 시작한 회기, 오래된 화면 상태는 서버에서 거부합니다. ±30분·±1시간 후보는 재협의 참고용이며 정확히 일치하지 않으면 확정할 수 없습니다.
6. 안내문을 복사해 기관 채널에서 직접 전달한 뒤 **실제 안내 완료로 기록**합니다. 복사·연결·실제 안내 완료는 별개입니다. 판단이 어려운 회기는 보류합니다.

날짜별 신청이 한 건이라도 있는 대기자는 주간 가능 시간 대신 날짜별 신청을 기준으로 판단합니다. `처리 대기` 신청만 후보에 포함됩니다. 정기 가능 시간만 관리하려면 직접 등록 방식을 사용하세요. 최근 연결에는 이미 확정한 미래 일정도 포함됩니다.

## CSV 형식

두 형식 모두 UTF-8(BOM 가능)·EUC-KR, 쉼표 구분, 큰따옴표 이스케이프를 지원하며 1MB 이하입니다. 원본 파일은 브라우저에서 해석한 뒤 폐기하고 검증된 필드만 서버에 보냅니다. 예시 파일은 가상 데이터이며 원하는 미래 날짜로 바꿔 사용하세요.

대기 명단: [예시](public/examples/participants.csv), 최대 1,000행.

```csv
가명 ID,치료,대기 시작일,희망 날짜,오전,오후,상태
대기자-SAMPLE01,작업치료,2026-01-01,2030-01-07,09:00,,처리 대기
```

- 가명 ID: `대기자-` 또는 `아동-` 뒤 영문 대문자·숫자 4~32자. 실명과의 대응표는 기관 내부 별도 관리.
- 서비스: 작업치료·물리치료·언어치료·감각통합·상담·교육·가족지원. 복수는 인용된 CSV 셀에서 쉼표로 구분.
- 시간: `09:00`은 30분 회기, `09:00–12:00`은 가능 범위. 여러 값은 인용된 셀 안에서 쉼표로 구분.
- 상태: 처리 대기·처리 완료·안내 완료·추가 확인 필요·신청 취소·만료.
- 동일 ID·날짜·서비스 중복은 거부합니다. 기존 동일 신청은 갱신하고 CSV에 없는 신청은 보존합니다. 명단의 동일 ID는 활성 상태로 갱신되므로 일시 중지 대상이 들어 있지 않은지 확인하세요.

시간표: [예시](public/examples/schedule.csv), 날짜별 최대 500회기.

```csv
일자,부서,담당자 코드,시작,종료,예약 코드
2030-01-07,작업치료,OT-01,09:00,09:30,SAMPLE01
```

- 날짜 형식은 `YYYY-MM-DD`, 시간 형식은 `HH:mm`입니다. 요일은 날짜에서 계산합니다.
- 운영 회기는 08:30–12:00 / 13:00–18:00, 정각 또는 30분 시작의 30분 회기입니다.
- 여러 날짜가 섞이면 반영을 거부합니다. 같은 날짜 시간표를 전체 교체하며 이미 등록된 결석·연결 회기를 제거하거나 변경하는 교체는 거부합니다.
- 예약 코드는 영문 대문자·숫자·`_`·`-` 1~24자이며 이름·주민번호·전화번호를 넣지 않습니다. CSV는 기관에서 사전에 가명화해야 합니다.
- 과거 10분 칸 현황판은 제한적으로 변환합니다. 30분 회기와 맞지 않으면 표준 양식으로 다시 작성해야 합니다.

## 개인정보와 저장 일관성

원문 문자 대신 허용된 일정 토큰만 외부 AI로 전송합니다. 이름·연락처·자유 서술은 추출 대상에서 제외하며, 생년월일로 의심되는 지난 날짜와 월일만 있는 날짜도 전송하지 않습니다. 전송 전 담당자가 표시된 내용을 확인합니다. 가명 데이터도 기관 정책에 따른 보호가 필요합니다.

Claude의 단일 `tool_use` 객체를 날짜·시간·서비스·담당자 코드 스키마로 검증하며 15초 제한을 둡니다. 오류 본문과 원문은 로그에 남기지 않습니다. [Claude 도구 입력 형식](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview)

저장마다 상태 버전을 확인하며 버전 갱신·변경·감사 로그를 D1 단일 트랜잭션으로 처리합니다. 다른 변경이 있거나 저장 오류가 나면 전체 롤백합니다. 화면은 성공 응답 후 DB를 다시 읽습니다. 저장 성공 뒤 재조회만 실패한 경우 이를 구별해 알립니다. 네트워크가 끊겨 응답을 못 받은 경우 새로고침 후 결과부터 확인하세요.

## 검증

```bash
npm run typecheck
npm test
npm run lint
npm run build
# 개발서버 실행 상태에서, 다른 터미널에서 실행
npm run test:ui
```

`npm test`는 가상 데이터와 메모리 SQLite에서 실제 마이그레이션 및 서버 처리 코드를 실행합니다. 100명 후보·CSV, 동률 정렬, 날짜별 신청, 중복/동시 연결, 저장 실패 롤백, 인증·출처 검사, 서울 자정 경계, AI 응답 및 실패 처리를 검증합니다. `test:ui`는 HTTP 응답과 기존 UI 컴포넌트 계약 검사이며 브라우저 클릭 테스트는 아닙니다. 결과 및 남은 확인 사항은 [실사용 전환 검증 보고서](실사용전환_검증보고서.md)에 기록합니다.

## 운영 전 확인할 한계

현재는 코디네이터가 기관 시간표와 대기 명단을 직접 반영하는 도구입니다. EMR·기존 기관 예약 시스템 및 문자 발송 API는 연결하지 않았습니다. 다른 시스템의 예약 충돌은 해당 시스템과 대조해야 합니다. 연결 확정 취소·완료 기록 수정 화면, 데이터 보존기간별 삭제·백업 복구 운영 절차는 별도 준비가 필요합니다. 감사 로그 화면은 최근 100건을 표시하고 DB에는 계속 보관합니다.

기관에서 실제 이용하기 전 허용 계정 로그인/차단, 외부 헤더 위조 차단, D1 백업·복구, 승인된 가명 데이터로 일정 일치 여부를 담당자가 확인해야 합니다. 자동 테스트 통과는 임상·현장 적합성 검증을 대신하지 않습니다.
